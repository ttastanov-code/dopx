ПОЧЕМУ ЭТОТ ФАЙЛ ПОЯВИЛСЯ (2026-08-21, по прямому запросу пользователя после живого теста retention loops — "кнопки кривые, непонятно, нельзя прочитать уведомление сразу в дропдауне"): раньше это были ДВЕ независимые вёрстки с разным поведением: - в дропдауне клик по строке НЕ отмечал уведомление прочитанным вообще (только переход по ссылке, без hx-post) — то есть колокольчик нельзя было "разгрести" не уходя на отдельную страницу; - на полной странице кнопки "Перейти"/"Прочитано" разъехались по стилю/ширине/hover-эффекту (первая — filled primary, вторая — outline success с лишним hover:scale-[1.02] и w-full/sm:w-28 через ДВА разных родительских контейнера) — то, что пользователь описал как "кривые". Единый партиал устраняет расхождение НА УРОВНЕ РАЗМЕТКИ, а не точечными CSS-подгонками, которые опять разъедутся при следующей правке одного из двух старых файлов. Переход по уведомлению — ОБЫЧНАЯ HTML-форма (POST + редирект на next), не hx-post на : так надёжнее (см. подробности в notifications/views.py ::MarkAsReadView) — работает гарантированно, без риска, что htmx перехватит клик по ссылке и отменит браузерную навигацию. Быстрая отметка "прочитано" (без перехода) — отдельная маленькая icon-кнопка, HTMX hx-post + hx-swap="outerHTML" на саму строку: ответ сервера — эта же строка в прочитанном виде + OOB-хвост счётчиков (см. notifications/views.py::_oob_counters_html). Именно эта кнопка чинит жалобу "нельзя прочитать сразу в дропдауне".
