Но на десктопе (3 колонки) нативный CSS Grid без `grid-auto-flow: dense` и без явного `grid-row` кладёт элементы В ОБЩИЕ строчные треки: высота каждой строки = высота САМОГО высокого элемента, попавшего в эту строку, и оба "виртуальных столбца" (левый col-span-2, правый col-span-1) синхронизированы по одним и тем же границам строк. У карточек в левой и правой колонках совершенно разная высота контента ("Составы команд" — гигантская, "Статистика" — крошечная), поэтому под короткими карточками справа оставались огромные пустые полосы высотой "пока не закончится соседняя высокая карточка слева". Это НЕ баг вёрстки конкретной карточки — это фундаментальное ограничение CSS Grid: он не умеет делать "две независимые по высоте колонки" без masonry (а `grid-template-rows: masonry` пока экспериментален и есть только в Firefox). ИСПРАВЛЕНИЕ: вернул оба wrapper-а колонок как независимые block-контейнеры (`space-y-*`, БЕЗ участия в grid-раскладке построчно) — см. templates/matches/detail.html. Карточка "ДНК матча" при этом должна быть на разных МЕСТАХ в DOM на мобильном и десктопе (мобильный — сразу после "События матча" в левой колонке; десктоп — между "За кого болели" и "Оценки команд" в правой), а не просто визуально переставлена — двумя независимыми `space-y-*` контейнерами это чисто CSS не сделать (нет аналога `order` между независимыми родителями). Поэтому карточка вынесена в этот partial и ВКЛЮЧЕНА ДВАЖДЫ — по разу в каждую колонку, но каждое включение показывается только на своём брейкпоинте через Tailwind-классы видимости (`lg:hidden` / `hidden lg:block`), переданные через `extra_class`. В DOM оба экземпляра присутствуют всегда, рендерится (visible) только один — это не хак, а стандартный паттерн "разное место в DOM на разных брейкпоинтах без JS", когда чистый CSS-reflow (order) недостаточен из-за разных родительских колонок. {% endcomment %} {% if match_dna %}
