# 0021 — daisyUI-цвета в стилях идут через CSS custom properties, не Tailwind-классы

Дата: 2026-08-22
Статус: Accepted

## Контекст

Кольцо вокруг аватара в "Живая сборная сезона"/"DOPX Лучшие тура" кодирует
доверие к рейтингу цветом (пусто/пунктир — слот не занят, янтарное — мало
голосов, изумрудное — данных достаточно) — премиальный паттерн вместо
отдельного текстового бейджа под каждой карточкой.

Баг, пойманный 2026-08-22: на этом сайте Tailwind загружен как отдельный
браузерный рантайм (`@tailwindcss/browser@4`), а daisyUI — отдельным
`<link>`-стилем, не как Tailwind-плагин/`@theme`. Tailwind поэтому не
знает про daisyUI-цвета `success`/`warning` как имена для генерации
утилит: класс `ring-success/80` тихо схлопывался в один и тот же
нейтральный дефолт для обоих состояний — кольца "данных достаточно" и
"данных мало" визуально не отличались вообще.

## Решение

`ring_style` — сырая CSS-строка через `outline` + `var(--color-*)`, а не
Tailwind-класс. `var(--color-success)`/`var(--color-warning)` — реальные
CSS custom properties, которые daisyUI ставит в `:root`, поэтому прямая
ссылка на них в `style` работает корректно в обход Tailwind. `outline`,
а не `box-shadow`-ring — см. докстринг `ring_style` в
`templates/components/_avatar.html` за отдельным обоснованием этого
выбора.

## Последствия

- **Общее правило для всего проекта, пока Tailwind и daisyUI загружены
  раздельно этим способом**: любой стиль, зависящий от именованного
  daisyUI-цвета (`success`/`warning`/`primary`/etc.) вне заранее собранных
  классов в CSS-файлах проекта, должен идти через `var(--color-*)` в
  инлайновом `style`, а не через Tailwind-утилитный класс вида
  `bg-success`/`text-warning`/`ring-primary` — такие классы либо не
  сгенерируются вовсе, либо тихо схлопнутся в нейтральный дефолт.
- Затрагивает любой будущий компонент с условной раскраской по
  доверию/статусу — не только кольцо аватара.
