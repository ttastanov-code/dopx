# 0023 — Не перезаписывать заголовки, которые curl_cffi формирует сам

Дата: 2026-09-01
Статус: Accepted

## Контекст

После добавления `curl_cffi` (TLS-фингерпринтинг для обхода блокировок
KFF) запросы всё равно получали `403`. `curl_cffi` при
`impersonate="chrome"` сам генерирует полный, согласованный с TLS-
отпечатком набор заголовков (`User-Agent`, `Accept`, `sec-ch-ua`,
`Sec-Fetch-*` — версия Chrome в них совпадает с версией, которую он
выдаёт себя за в TLS ClientHello). Ручной `User-Agent`, заданный отдельно
(усечённая строка без версии Chrome/Safari в конце), затирал этот
согласованный набор — получалось "TLS настоящего свежего Chrome, а в
заголовке огрызок UA, которого ни один реальный браузер не шлёт". Это
классический сигнал для Cloudflare Bot Management (рассогласование
TLS/заголовков) — вероятно, именно он и не давал `curl_cffi` помочь.

## Решение

`curl_cffi` формирует профильные заголовки браузера сам — они не
перезаписываются. Устанавливаются вручную только контекстные заголовки
(`Referer`/`Origin`), не являющиеся частью браузерного профиля.

## Последствия

- Любое будущее добавление заголовков к этой сессии должно проверяться на
  конфликт с набором, который формирует `impersonate=` — не добавлять
  ничего, что перезаписывает `User-Agent`/`Accept`/`sec-ch-ua`/`Sec-Fetch-*`.
