# 0018 — X-Forwarded-For разбирается с конца, не с начала

Дата: до докеризации (найдено при аудите)
Статус: Accepted

## Контекст

`core.utils.get_client_ip` определяет реальный IP клиента для rate-limit и
анти-фрод сигналов. `TRUSTED_PROXY_COUNT` — сколько доверенных обратных
прокси реально стоит перед Gunicorn (в типовой схеме nginx → gunicorn — 1).

Раньше брался первый элемент `X-Forwarded-For` — этот элемент целиком
контролируется клиентом (любой может отправить произвольный
`X-Forwarded-For: 1.2.3.4` напрямую), что позволяло обойти IP rate limit
одной строкой заголовка.

## Решение

`get_client_ip` берёт IP-адрес на позиции `TRUSTED_PROXY_COUNT` считая с
конца цепочки `X-Forwarded-For`, а не первый элемент. nginx с
`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;` дописывает
реальный IP клиента в конец заголовка, а не заменяет его — значит именно
последний элемент нельзя подделать снаружи (всё, что левее него в списке,
атакующий мог вписать сам).

**Это не заменяет требование закрыть прямой доступ к Gunicorn извне**
(файрвол/security group) — без этого шага даже правильный разбор XFF не
спасает: атакующий, зашедший напрямую в обход nginx, пришлёт заголовок с
одним (подделанным) элементом, и он и окажется "последним" с точки зрения
`TRUSTED_PROXY_COUNT=1`. См. `docs/BACKLOG.md` для статуса этого пункта
инфраструктуры.

## Последствия

- `TRUSTED_PROXY_COUNT` должен точно соответствовать реальному числу
  прокси перед Gunicorn — при изменении сетевой топологии (добавление
  ещё одного балансировщика перед nginx и т.п.) это значение нужно
  синхронно поднять, иначе разбор снова возьмёт не тот элемент цепочки.
