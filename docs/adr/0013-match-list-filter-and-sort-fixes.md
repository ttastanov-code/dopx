# 0013 — Список матчей: фильтрация и сортировка (`matches/views.py`)

Дата: 2026-09-01 (с более ранними находками того же кластера)
Статус: Accepted

## Контекст

Три отдельные находки в фильтрации/сортировке `MatchListView`, все — в
одном методе (`get_queryset`), сгруппированы одним ADR как части одной и
той же истории приведения списка матчей в порядок.

### 1. Фильтр "Перенесённые" не работал вообще

`status='postponed'`/`'cancelled'` не было ни в одной ветке `elif` —
фильтр молча падал в `else` и показывал вообще все матчи без разбора
статуса.

**Решение**: добавлена явная ветка `elif status == 'postponed'`.
Расширена (2026-09-01): `status='postponed'` ловит только матчи, у
которых KFF ещё не определился с датой (`is_schedule_tentative`, см.
ADR-0007). Матч с уже твёрдой датой, но всё равно выбившийся из своего
тура (`Match.was_rescheduled`) — тоже "Перенесён" с точки зрения
пользователя, просто ему уже не имеет смысла оставаться в
`status='postponed'` (это заблокировало бы приём прогнозов через
`is_prediction_open()`). Фильтр объединяет оба случая
(`Q(status='postponed') | Q(was_rescheduled=True, status__in=['scheduled', 'live'])`),
исключая `finished`/`cancelled` — те показываются в своих собственных
вкладках независимо от истории переноса.

### 2. Виртуальный статус "Оценено" вёл на общий список матчей

Кнопка "Все матчи" в блоке "Последние оценки" профиля вела на список всех
матчей вообще, а не на те, что пользователь реально оценил
(`profile/dashboard.html` показывает только последние 10 —
`recent_evaluations` — полного списка нигде не было).

**Решение**: `status='evaluated'` — виртуальный статус (не значение поля
`Match.status`), доступный только по прямой ссылке из
`profile/dashboard.html`, не в выпадающем списке фильтров
(`templates/matches/list.html`). Источник истины —
`EvaluationSession.status='completed'`, а не наличие связанных
`PlayerEvaluation`/`TeamEvaluation`/etc. — тот же принцип, что и в
`ProfileView.get_context_data()` (`users/views.py`) при подсчёте
`recent_evaluations`/`total_matches`, чтобы число "Матчей оценено" в
статистике профиля и список за ссылкой "Все матчи" совпадали 1:1.

### 3. Сортировка "по близости к сегодня" ломала группировку по дате

Сортировка по симметричному расстоянию `|start_time - now|` (идея —
показать самые актуальные матчи первыми) ломала `{% regroup %}` по дате в
шаблоне (`matches/list.html`): группа "будущее +2 дня" оказывалась ближе
по этой метрике, чем "прошлое −1 день", поэтому даты в списке прыгали
вперёд-назад.

**Решение**: обычный возрастающий порядок по `start_time` — единственный,
при котором даты идут монотонно и группы не повторяются и не скачут.
Чтобы не терять исходную идею "показать актуальное первым", стартовая
страница вычисляется в `paginate_queryset()` — рядом с сегодняшним днём, а
не с первой страницы отсортированного списка целиком.

## Последствия

- Все три фильтра/сортировки покрыты `matches/tests.py` (существующие
  тесты списка матчей).
