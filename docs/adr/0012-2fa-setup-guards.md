# 0012 — 2FA-настройка: две находки в `dashboard/views_2fa.py::two_factor_setup`

Дата: 2026-09-01
Статус: Accepted

## Контекст

Два независимых бага в первичной настройке 2FA для сотрудников, оба —
классический класс "код выглядит правильным, но условие проверяет не то,
что кажется".

### 1. Генератор всегда truthy

`devices_for_user(...)` возвращает генератор. `if <генератор>:` в Python
всегда `True` — проверяется сам факт наличия ссылки на объект, а не то,
даст ли итерация хоть один результат. Из-за этого условие "уже есть
подтверждённое устройство → редирект на challenge" срабатывало даже при
нуле устройств в базе, и `/setup/` безусловно уводил на `/verify/` —
пользователь никогда не видел QR-код, даже настраивая 2FA впервые.
`dashboard/middleware.py` этот баг не воспроизводил — там уже
использовался `any()`.

**Решение**: материализовать генератор через `any(devices_for_user(...))`
перед проверкой истинности.

### 2. Повторный проход `setup` копил дублирующиеся backup-коды

Backup-коды генерируются ровно один раз — в момент первичного
подтверждения устройства (`StaticToken` хранит значение в открытом виде
в БД, но UI больше никогда его не показывает повторно). Раньше здесь
стоял голый `.create()` — при повторном прохождении setup (например,
старое confirmed-устройство было удалено вручную из БД, а `StaticDevice`
от предыдущего захода остался) накапливались второй `StaticDevice` + его
`StaticToken`'ы. `devices_for_user()` в `two_factor_challenge` перебирает
все confirmed static-девайсы сразу — верными считались коды из старой
пачки, которую пользователь уже не видит, а из новой показанной пачки —
только тот код, что случайно не совпал по префиксу/коллизии со старым.
Симптом в проде: "один код почему-то всегда работает, остальные — никогда"
— рабочий код на самом деле был из старой, забытой пачки.

**Решение**: явная зачистка (`StaticDevice.objects.filter(user=...).delete()`)
перед созданием нового набора backup-кодов.

## Последствия

- Оба фикса — защитное программирование против повторного прохождения
  одного и того же view, а не изменение бизнес-логики 2FA.
