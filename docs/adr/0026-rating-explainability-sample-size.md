# 0026 — Видимость размера выборки в рейтингах игроков

Дата: 2026-09-05
Статус: Accepted

## Контекст

`docs/CODEX_AUDIT_RESPONSE_2026-09-04.md` (корзина В, бэклог идей)
фиксировал незакрытую находку продуктового аудита ("доверие к рейтингу"):
"показывать число оценок и пометку 'предварительный рейтинг' при
маленькой выборке". Аудит рейтинг-страниц перед закрытием этого пункта
показал, что состояние было НЕПОСЛЕДОВАТЕЛЬНЫМ, а не просто
"недоделанным":

- `templates/players/leaderboard.html` — уже гейтит рейтинг через
  `has_enough_votes`, число оценок видно отдельной колонкой.
- `templates/players/detail.html`, `templates/teams/detail.html` — число
  оценок видно, гейт не нужен (это профиль конкретной сущности, не
  сравнительный топ).
- `templates/players/list.html` (основной список/поиск игроков) —
  рейтинг показывался БЕЗ гейта и без индикатора вообще: `.only('id',
  'performance_score', 'player_id')` в `players/views.py::PlayerListView`
  даже не подгружал `total_votes` в память, так что гейт нельзя было
  добавить в шаблон, даже если бы кто-то захотел.
- `core/views.py::HomeView` ("Топ игроков" на главной) — queryset
  `PlayerMatchAggregate.objects.order_by('-performance_score')[:5]` вообще
  без фильтра по числу голосов: единичный накрученный голос "10.0" от
  друга игрока НАВЕРХУ витрины сайта обходил игроков с честными десятками
  оценок. Тот же класс проблемы, который уже закрыт для топа игроков
  команды (`docs/adr/0014-team-top-players-transfer-fix.md`), но пропущен
  именно на главной странице.

## Решение

**1. `players/views.py::PlayerListView.get_queryset`** — `total_votes`
добавлен в `.only(...)` для `best_aggregate` Prefetch, чтобы поле вообще
было доступно в шаблоне.

**2. `templates/players/list.html`** — рейтинг гейтится через
`has_enough_votes` (как в leaderboard.html) + добавлен
`{% confidence_badge %}` рядом с числом.

**3. `core/views.py::HomeView.get_context_data`** — `top_players` теперь
фильтруется `total_votes__gte=MIN_VOTES_FOR_DISPLAY` ДО сортировки по
`performance_score`. Это реальный фикс queryset (не косметика уровня
шаблона) — единичный голос больше не может попасть в витрину топа вообще,
независимо от того, показывается ли рядом бейдж.

**4. `templates/core/home.html`** — подпись "рейтинг" под числом заменена
на "{{ agg.total_votes }} оценок" — раз виджет теперь и так фильтрует по
минимальному порогу, показывать сам счётчик достаточно, отдельный бейдж
избыточен для уже отфильтрованной витрины.

**5. `core/templatetags/rating_extras.py::confidence_badge`** — число
оценок теперь ПРЯМО в видимом лейбле бейджа ("Предварительно · 3"), не
только в тултипе по наведению, но ТОЛЬКО для tier `preliminary`. Именно
маленькая выборка — случай, где пользователю важнее всего увидеть цифру
сразу, не наводя курсор; для `basic`/`high` статичный лейбл ("Есть
данные"/"Высокая надёжность") оставлен как есть, чтобы не перегружать
таблицы числами там, где доверие и так не под вопросом.

## Альтернативы и почему не они

- **Показывать число оценок во ВСЕХ трёх уровнях бейджа** — рассмотрено,
  отклонено: в плотных таблицах (leaderboard, list.html) это добавляет
  визуальный шум там, где рейтинг и так уже прошёл порог доверия; число
  остаётся доступным в тултипе для тех, кому интересно.
- **Фильтровать `players/list.html` по `MIN_VOTES_FOR_DISPLAY` в queryset
  (как для HomeView), а не гейтить в шаблоне** — отклонено: это страница
  поиска/каталога, а не "топ" — игрок с маленькой выборкой должен
  оставаться находимым по имени, просто без авторитетного числа рядом.

## Последствия

- Тесты: `core/tests.py::ConfidenceBadgeSampleSizeTests` (инлайн-счётчик
  только на preliminary), `core/tests.py::HomeTopPlayersVoteGateTests`
  (единичный голос не проходит в топ на главной).
- Любая новая "топ N" витрина по `PlayerMatchAggregate`/аналогичным
  моделям должна с самого начала фильтровать по `MIN_VOTES_FOR_DISPLAY` —
  это уже третье отдельное место (команда, HomeView, теперь и это), где
  забытый фильтр создавал бы одну и ту же дыру доверия.
