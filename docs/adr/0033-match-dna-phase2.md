# 0033 — Match DNA, фаза 2: герой матча, спорный эпизод, консенсус, шаринг

Дата: 2026-09-07
Статус: Accepted

## Контекст

ADR-0028 (фаза 1) сознательно ограничился текстовой секцией без шаринговой
карточки — обоснование: "цена ошибки на карточке выше, чем на текстовой
секции, поэтому карточка — только после проверки, что секция вообще
востребована" (см. `docs/PRODUCT_SCOPE_MATCH_DNA_AND_EXPLAINABILITY.md`).

Прямой продуктовый запрос по итогам второго аудита переопределяет эту
паузу явно: карточку нужно делать сейчас, не дожидаясь метрик
использования секции фазы 1 (в проекте и не было отдельного трекинга
открытия именно этой секции, чтобы измерить востребованность — это
зафиксировано как сознательное отклонение от собственной рекомендации
документа, не забытый шаг).

Отдельно вторым аудитом перечислен конкретный список того, чего в фазе 1
не хватало по содержанию: "герой матча, главный спорный эпизод, разрыв
мнений фанатов [уже было — referee_divergence], оценка судейства,
переломный момент, уровень консенсуса".

## Решение

### Контентные добавления в `build_match_dna` (matches/services.py)

Все четыре — композиция уже существующих данных, ни одного нового поля в
БД (тот же принцип, что и вся фаза 1):

- **Герой матча** (`_describe_hero`) — первая строка уже отфильтрованного
  и отсортированного `top_players` (`PlayerMatchAggregate`, `total_votes >=
  MIN_VOTES_FOR_DISPLAY`, `order_by('-performance_score')`), который
  `matches/views.py::MatchDetailView` и так уже вычисляет для блока "Топ
  игроков матча" — ни одного нового запроса.
- **Переломный момент** (`_describe_turning_point`) — `MatchAggregate.turning_point_ratio`
  уже посчитан (`aggregates/tasks.py::recalculate_match_aggregate`), но
  нигде не выводился пользователю (данные есть, витрины не было — та же
  формулировка, что во втором аудите про P0-баг). Гейт `TURNING_POINT_MIN_RATIO=0.3`
  — меньше трети голосовавших отметили чекбокс — не показываем фразу
  вообще, а не подаём слабый сигнал как значимый.
- **Уровень консенсуса** (`_consensus_level`) — population stdev
  КОМПОЗИТНОЙ оценки каждого голосовавшего (`(entertainment+tension+fairness)/3`),
  а не stdev уже усреднённых по всем голосам чисел (это была бы ошибка
  дисперсии среднего, а не разброса мнений). Требует сырых
  `MatchEvaluation` этого матча — единственное место фазы 2, где нужен
  дополнительный (лёгкий, `.only()` по 3 полям) запрос, которого не было в
  фазе 1.
- **Главный спорный эпизод** (`_describe_controversial_episode`) —
  эвристика, ЯВНО задокументированная как эвристика в докстринге функции
  (продукт не проводит отдельного голосования "самый спорный момент"):
  1) отменённый гол (`disallowed_goal`) — самый однозначный доступный
     прокси, решение спорно по определению; 2) иначе красная карточка,
     показанная ТОЛЬКО если фанаты разошлись во мнениях о судействе
     (`REFEREE_DIVERGENCE_MIN_GAP`, тот же порог, что у уже существующего
     `_describe_referee_divergence`) — без этого гейта обычная красная
     карточка слишком частое событие футбола, чтобы называть её "спорной";
     3) иначе — пустая строка, эвристика не гадает при отсутствии сигнала.

### Шаринговая карточка (`build_match_dna_share_card`, `core/services/share_cards.py`)

Отдельная функция от уже существующей `build_match_share_card` (та
осталась og:image-карточкой ссылки на страницу матча — счёт + топ-игрок,
используется на месте, где была раньше). Новая карточка — под ПРЯМОЙ
шеринг содержимого секции "ДНК матча": drama_level/index, герой, и ОДНА
"headline"-строка (приоритет выбирает вызывающая сторона,
`MatchDNAShareCardView` — controversial_episode, иначе referee_divergence,
иначе turning_point_text — та же логика приоритета, что на самой странице
матча в `templates/matches/detail.html`).

Доступ — `/share/match/<uuid:match_id>/dna-card.png`
(`core:match_dna_share_card`), 404 если по матчу ещё нет голосов (то же
условие, что у самой секции). Кнопка "Поделиться" на карточке ДНК матча —
Web Share API + фолбэк на `window.open`, ТОТ ЖЕ паттерн, что уже
использован в `templates/users/badge_catalog.html` для карточек
достижений (шерим прямую ссылку на PNG, не URL страницы — картинка должна
открываться одним нажатием, а не превью ссылки).

## Альтернативы и почему не они

- **Отдельное голосование "самый спорный момент матча"** — отклонено на
  этом этапе: новый UI-элемент в вайзарде оценки, который уже и так
  подвергался критике за перегруженность (см. ADR-0031, quick-mode); эвристика
  на существующих данных дешевле и достаточно честна ПРИ УСЛОВИИ явного
  документирования её ограничений (что и сделано).
- **Хранить `consensus_level`/`hero` как поля `MatchAggregate`, считаемые
  Celery-задачей** — рассмотрено, отклонено: `consensus_level` требует
  сырых голосов только один раз при рендере страницы матча (не горячий
  путь сайта), заводить новое поле + миграцию + правку Celery-таски ради
  вычисления, которое дешевле сделать на чтении, увеличивало бы
  поверхность синхронизации (что если Celery-таска не успела пересчитать
  после последнего голоса — секция показывала бы устаревший uровень
  консенсуса).

## Последствия

- Новый лёгкий запрос на страницу матча (`MatchEvaluation.objects.filter(match=match).only(...)`)
  — обоснованно, страница матча и так делает похожие точечные запросы
  ради каждого блока (top_players, coach_aggregates и т.д.), не самый
  горячий путь сайта.
- `MatchDNAShareCardView` дублирует часть логики `MatchDetailView.get_context_data`
  (свой запрос `top_players`, `events`, `referee_agg`) — сознательно НЕ
  переиспользует контекст вьюхи страницы матча, это отдельный HTTP-запрос
  без сессии рендера страницы; ограничен `top_players[:1]` — карточке
  нужен только герой, не топ-5.
- Отсутствие baseline-метрики использования секции фазы 1 до появления
  кнопки "Поделиться" — see `docs/PRODUCT_SCOPE_MATCH_DNA_AND_EXPLAINABILITY.md`
  (раздел "ЕЩЁ РАЗ УСТАРЕЛО") — не позволит оценить, действительно ли
  секция "прижилась" отдельно от эффекта самой кнопки шеринга.
- Тесты: `matches/tests.py` дополнен для `_describe_hero`,
  `_describe_turning_point`, `_consensus_level` (высокий/средний/низкий/None),
  `_describe_controversial_episode` (disallowed_goal/red_card+gap/пусто).
