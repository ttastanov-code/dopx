# 0025 — Убрать рантайм-зависимость от cdn.jsdelivr.net

Дата: 2026-09-05
Статус: Accepted (план подготовлен и частично реализован; активация — см. чеклист ниже)

## Контекст

`templates/base.html`/`base_auth.html` грузят шесть пакетов напрямую с
`cdn.jsdelivr.net` при каждой загрузке страницы: `@tailwindcss/browser@4.3.3`
(Tailwind JIT-компилятор, работающий В БРАУЗЕРЕ пользователя — не собранный
CSS-файл, а полноценный компилятор, компилирующий классы на лету при каждом
визите), `daisyui@5.7.17` + `daisyui@5.7.17/themes.css`,
`@tabler/icons-webfont@3.46.0`, `@alpinejs/csp@3.15.8`,
`@alpinejs/collapse@3.15.8`, `htmx.org@2.0.8`.

Это внешний аудит (`docs/CODEX_AUDIT_RESPONSE_2026-09-04.md`) отметил как
риск готовности к продакшену:
- **Производительность**: `@tailwindcss/browser` — не просто CSS-файл, а
  весь JIT-движок Tailwind, компилирующий классы в браузере при каждой
  загрузке страницы. Это заметно тяжелее и медленнее одного собранного
  CSS-файла с уже готовыми классами.
- **Отказоустойчивость**: любой сбой/блокировка/деградация jsDelivr кладёт
  вёрстку и интерактивность сайта целиком — шесть внешних точек отказа на
  каждой странице.
- **Согласованность**: `daisyUI` подключён отдельным `<link>`, а не как
  настоящий Tailwind-плагин — из-за этого Tailwind не знает про
  daisyUI-именованные цвета для генерации утилит (`ring-success` и т.п.
  тихо не работают, см. `docs/adr/0021-tailwind-runtime-daisyui-colors.md`)
  — обходной путь через `var(--color-*)` работает, но не должен быть
  единственным вариантом.
- **integrity= на Tailwind был временно снят** (см. комментарий в
  `base.html`, `docs/adr/0017`...`0024` серия правок этой же сессии не
  трогала этот файл намеренно, до появления настоящего плана) — SRI-хэш
  на плавающую CDN-зависимость и так требует ручного пересчёта при каждом
  обновлении версии (`scripts/generate_sri.sh`), локальная сборка снимает
  и этот источник трения полностью.

## Решение

Два независимых механизма — Tailwind/daisyUI требуют настоящей сборки,
остальные четыре пакета достаточно один раз скачать и отдавать самим:

**1. Tailwind v4 + daisyUI — локальная сборка через `@tailwindcss/cli`.**
`static_src/app.css` — CSS-first точка входа (`@import "tailwindcss";
@plugin "daisyui" { themes: light --default, dark; }`), компилируется в
`static/css/app.css` командой `npm run build:css` (`package.json`).
daisyUI подключён как настоящий Tailwind-плагин — Tailwind получает
реальное знание об именованных цветах daisyUI, устраняя первопричину
`docs/adr/0021` (обходной путь через `var(--color-*)` остаётся рабочим и
не отменяется — он не завязан на то, откуда взят Tailwind — но перестаёт
быть единственным вариантом для новых компонентов).

**2. Alpine CSP, Alpine Collapse, HTMX, Tabler Icons webfont — просто
вендоринг.** Эти четыре не требуют сборки — `scripts/vendor_frontend_assets.sh`
скачивает те же самые закреплённые версии, что сейчас в `base.html`, в
`static/vendor/` один раз. SRI/`integrity=` после этого не нужен — файлы
same-origin, `scripts/generate_sri.sh` (пересчёт хэша для чужого домена)
для них перестаёт быть релевантен.

**Docker**: `Dockerfile` получил стадию `frontend-builder` (`node:22-slim`)
перед существующими Python-стадиями — `npm ci && npm run build:css`,
результат копируется в `runtime`-стадию поверх основного `COPY`. Тот же
принцип builder/runtime-разделения, что и у Python-зависимостей: сама
Node/npm-тулза не попадает в финальный образ.

`static/css/app.css` и `static/vendor/**` — коммитятся в git (как и
остальные ручные файлы `static/css/*.css`), не игнорируются: это не
`STATIC_ROOT`-выход `collectstatic`, а зафиксированные собранные/скачанные
ассеты репозитория, регенерируемые вручную (`npm run build:css` /
`scripts/vendor_frontend_assets.sh`) при изменении версий или добавлении
новых Tailwind-классов в шаблоны. Docker-стадия `frontend-builder`
пересобирает CSS заново при каждой сборке образа независимо от того,
закоммитирован ли актуальный `app.css` — подстраховка на случай, если
разработчик забыл пересобрать перед пушем.

## Почему это НЕ было активировано в этой же сессии

Песочница, в которой подготовлен этот план, не имеет сетевого доступа к
реестрам пакетов (`npm view` возвращает `403 Forbidden` через
allowlist-прокси — тот же класс ограничения, что не позволил прогнать
`pip-audit`, см. `docs/CODEX_AUDIT_RESPONSE_2026-09-04.md`). Из-за этого
`npm ci`/`npm run build:css`/`scripts/vendor_frontend_assets.sh` не были
реально запущены и результат не проверен визуально. Переключать
`base.html` на файлы, существование и корректность которых не подтверждены,
означало бы рисковать сломать вёрстку ВСЕГО сайта локально — то есть ровно
то, что явно запрещено ("не ломать текущий локальный сервер"). Поэтому
`base.html`/`base_auth.html` и CSP-политики в `dopx/middleware.py`
намеренно НЕ тронуты — CDN-теги продолжают работать как раньше, пока
кто-то с реальным доступом к сети не пройдёт чеклist ниже.

## Чеклист активации (выполняется человеком с доступом к npm-реестру)

1. `npm install` (создаст `package-lock.json`) → `npm run build:css` →
   открыть сайт локально и глазами сверить со снимком до правки (в
   частности: `ring-success`/`ring-warning` из
   `docs/adr/0021-tailwind-runtime-daisyui-colors.md`, кастомные
   `.match-card`/`.wz-*`/`.md-hero`/`.badges` классы из
   `static/css/{match-card,wizard,match-detail,badges}.css` — эти файлы
   не входят в Tailwind-сборку и продолжают подключаться отдельными
   `<link>`, как сейчас).
2. `bash scripts/vendor_frontend_assets.sh` → проверить, что
   `static/vendor/tabler-icons/tabler-icons.min.css` резолвит шрифты
   локально (открыть DevTools → Network, иконки должны грузиться с
   `/static/vendor/...`, не с `cdn.jsdelivr.net`).
3. В `templates/base.html` и `templates/base_auth.html` заменить 6
   CDN-тегов на локальные (`{% static_v 'css/app.css' %}`,
   `{% static_v 'vendor/alpine/alpine-csp.min.js' %}`,
   `{% static_v 'vendor/alpine/alpine-collapse.min.js' %}`,
   `{% static_v 'vendor/htmx/htmx.min.js' %}`,
   `{% static_v 'vendor/tabler-icons/tabler-icons.min.css' %}`) — убрать
   `integrity=`/`crossorigin=` (не нужны для same-origin).
4. В `dopx/settings.py`/`dopx/middleware.py::ContentSecurityPolicyMiddleware`
   убрать `https://cdn.jsdelivr.net` из `script-src`/`style-src`/
   `font-src`/`connect-src` в `POLICY`, `ADMIN_POLICY` и
   `WIDGET_POLICY_BASE` — после миграции ни один запрос со страницы не
   должен идти на этот домен вообще, оставлять его в allow-list незачем.
5. `bash scripts/generate_sri.sh` — удалить/закомментировать шаги для
   4 провендоренных пакетов (Alpine CSP/Collapse, HTMX, Tabler) — им
   больше не нужен `integrity=`; шаг для Tailwind/daisyUI удалить целиком
   (сборка, не CDN-тег).
6. Прогнать полный набор Django-тестов + вручную открыть 5-10 ключевых
   страниц (главная, страница матча, вайзард оценки, профиль, admin) —
   визуально сверить с текущим продакшеном/локалью до правки.
7. Обновить эту ADR: статус → `Accepted` (без пометки "план"), убрать
   раздел "Почему не активировано".

## Addendum (2026-09-07): `npm ci` ломал сборку без лок-файла

Реальный `docker compose ... up --build` на машине с сетевым доступом
упал на `frontend-builder`: `npm ci` требует существующий
`package-lock.json`/`npm-shrinkwrap.json`, а в репозитории его нет (см.
раздел выше — песочница не смогла его сгенерировать без доступа к
npm-реестру). Это оказалось НЕ инертным изменением, как предполагалось:
`Dockerfile`-стадия выполняется при КАЖДОЙ сборке образа независимо от
того, подключён ли `app.css` в `base.html` — активация шаблонов и
рабочая сборка Docker-образа оказались двумя разными вещами, и вторая
сломалась раньше первой.

**Временный фикс**: `RUN npm ci` → `RUN npm install` в `frontend-builder`
(работает без лок-файла, `docker compose build` больше не падает).

**Окончательный фикс (2026-09-07)**: `package-lock.json` сгенерирован
(`npm install` на машине с доступом к npm-реестру, 34 пакета) и
закоммичен в репозиторий. `Dockerfile` возвращён к `RUN npm ci` с
обязательным (не `package-lock.json*`) COPY лок-файла — если его снова
не окажется в репозитории, сборка теперь падает явно на шаге COPY, а не
загадочной ошибкой EUSAGE внутри `npm ci`.

## Альтернативы и почему не они

- **Оставить CDN, только исправить integrity=** — не решает проблему
  клиентского JIT-компилятора Tailwind (главный источник производительности
  и единой точки отказа) и не даёт daisyUI стать настоящим плагином.
- **Самостоятельно писать Tailwind-совместимый CSS вручную, без сборки** —
  отклонено: теряется JIT-генерация утилит по мере роста шаблонов,
  пришлось бы вручную поддерживать полный список используемых классов.
- **Vendoring вместо сборки и для Tailwind/daisyUI (просто скачать готовый
  CSS с CDN один раз)** — рассмотрено для симметрии с Alpine/HTMX/Tabler,
  но отклонено: `@tailwindcss/browser` — не готовый CSS-файл, а
  JS-компилятор без собственного статического CSS-вывода для скачивания;
  скачать "как есть" нечего, нужна настоящая сборка через CLI.

## Последствия

- До прохождения чеклиста активации сайт продолжает грузить 6 пакетов с
  `cdn.jsdelivr.net`, как и раньше — это НЕ регрессия, это сохранение
  текущего рабочего поведения до подтверждённой замены.
- После активации: добавление НОВОГО Tailwind-класса в шаблон требует
  `npm run build:css` (или `npm run watch:css` во время разработки) —
  не подхватится сам по себе, как раньше в браузерном JIT-режиме. Это
  единственное поведенческое отличие для повседневной разработки.
- Обновление версии Tailwind/daisyUI — правка версии в `package.json` +
  пересборка. Обновление версии Alpine/HTMX/Tabler — правка URL/версии в
  `scripts/vendor_frontend_assets.sh` + повторный запуск.
