# 0010 — Точное определение слота формации через amplua+field_position

Дата: 2026-08-23
Статус: Accepted

## Контекст

"Живая сборная сезона" (`season_squad`) и "DOPX Лучшие тура" (`round_squad`)
маппят слоты формации 4-3-3 на пулы допустимых кодов позиций
(`players/positions.py`). Реальный набор сырых кодов, которые присылает
KFF в поле `amplua`/`position`, — всего 6 штук: `GK`, `D`, `DM`, `M`, `AM`,
`F`, без разделения по флангу. Из-за этого `CB1`/`CB2`/`RB`/`LB` делили
один и тот же пул `D` (сторону невозможно было определить), а вингеры
`RW`/`LW` стояли на приблизительном фолбэке `AM`/`F`.

Обнаружено, что в том же ответе `/games/<id>/lineup` у каждого игрока есть
ещё одно поле — `field_position` (`C`/`L`/`R`/`LC`/`RC` — колонка
формации), которое не импортировалось (см. `parsers/kff/importers.py` и
`lineups/models.py::MatchLineupPlayer.field_position`). Комбинация
`amplua`+`field_position` даёт точный слот без фолбэков-угадаек.

## Решение

`_resolve_lineup_codes()` сворачивает `field_position` в 3 зоны (`L`/`C`/`R`
— `LC` и `RC` обе схлопываются в `C`, поскольку в формации `CB1`/`CB2`
взаимозаменяемы, отдельного слота "левый ЦЗ" не существует) и возвращает
комбинированный код вида `"D:L"` — но только если `field_position` реально
известен.

Обратная совместимость: если это старая запись (синк до введения
`field_position`, поле пустое) — возвращается голый код `"D"`, как раньше,
без комбинирования. Это принципиально: старые данные регистрируются
только под голым кодом (общий пул на все 4 защитных слота, как было
всегда), а новые — только под точным комбинированным (не дублируются в
голый пул, иначе левый защитник с известной стороной снова попадал бы в
конкуренты на ЦЗ). Голые коды остаются в списках как приёмник именно для
старых записей — не для новых, где сторона уже известна.

## Альтернативы и почему не они

- **Обратный бэкафилл `field_position` для всех старых записей** —
  отклонено: потребовало бы повторного полного ре-импорта составов всех
  прошедших матчей ради поля, которое не критично для уже сыгранных игр.
- **Единый пул без разделения на "голый"/"комбинированный" код** —
  отклонено: воссоздало бы исходную проблему конкуренции CB1/CB2/RB/LB за
  один пул для новых записей, у которых сторона уже известна.

## Последствия

- Слот игрока в формации зависит от того, был ли `field_position` известен
  на момент импорта его конкретной записи в составе — не ретроактивно
  меняется для старых матчей без повторного импорта.
