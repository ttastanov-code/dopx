# 0009 — Анти-бригадинг: расхождение с объективной статистикой KFF

Дата: 2026-08-23
Статус: Accepted

## Контекст

Продуктовый запрос: использовать объективную статистику матчей KFF (удары,
угловые и т.д.) как независимый анти-фрод сигнал. Все предыдущие детекторы
(`vote_spike`, `ip_cluster`, `extreme_bias`, градуированный штраф веса) в
конечном счёте смотрят на сами голоса — скоординированный сговор, который
ставит не крайние 1/10, а просто слегка смещённые оценки (например, 8-10
своим, 5 чужим), может оставаться ниже порогов всех этих детекторов сразу.
Объективные факты матча не зависят от голосов DOPX и не поддаются
"умеренному" сговору в чате.

## Решение

Метрика "доля доминирования" (dominance share) — доля команды в сумме
показателя (удары/угловые/etc.) обеих команд этого же матча
(`own / (own + opponent)`, 0.5 = паритет). Намеренно не используются сырые
счётчики: разные матчи имеют разную интенсивность игры, а доля
самокалибруется без ручной настройки "нормальных" значений.

Если рейтинг команды у сообщества устойчиво идёт вразрез с тем, как
команда объективно играла в последних `STATS_DIVERGENCE_WINDOW_MATCHES`
матчах — это проверяемый, объяснимый признак предвзятости.

Как и все остальные анти-фрод сигналы, это мягкий сигнал для очереди
ручной модерации (`SuspiciousActivityFlag`), а не автоматическая коррекция
рейтинга: xG/передачи часто `null` у KFF, у команды может быть объективно
оправданная причина (травмы, судейство, перестройка состава) — решение
всегда за модератором (`dashboard/antifraud`), не за кодом.

## Альтернативы и почему не они

- **Автоматическая коррекция рейтинга по расхождению** — отклонено:
  слишком много легитимных причин для реального расхождения (см. выше),
  риск ложной коррекции рейтинга честной команды.
- **Абсолютные пороги ударов/угловых вместо доли** — отклонено: не
  учитывает разную интенсивность игры между матчами, потребовало бы
  ручной перенастройки порогов.

## Последствия

- Пороги (`STATS_DIVERGENCE_DOMINANCE_HIGH/LOW`, окна матчей) подобраны
  эвристически — кандидат на пересмотр по мере накопления реальных
  случаев модерации.

## Дополнение: baseline пересекался с окном расхождения (найдено позже)

Baseline (историческая норма) считался по тому же срезу `aggregates[:fetch_limit]`,
из которого окно расхождения (`window_pairs`) брало первые
`STATS_DIVERGENCE_WINDOW_MATCHES` матчей — то есть окно было подмножеством
baseline, baseline подтягивался к окну, и реальное расхождение занижалось.

**Фикс**: baseline считается только по матчам старше окна
(`aggregates[STATS_DIVERGENCE_WINDOW_MATCHES:]`), не пересекаясь с ним.

**Остаточный риск (сознательно не устранён, требует более широкого
рефакторинга)**: `baseline_scores` берутся из `performance_score`, который
уже может включать применённую на прошлых прогонах `TeamRatingCorrection`
— то есть возможна обратная связь (поправка чуть смещает baseline
следующего прогона). Полностью убрать это можно только пересчитав "сырой"
`performance_score` без коррекции, для чего сейчас нет отдельного поля.
