# 0008 — KFF-импорт: защита исторических данных от повторного синка

Дата: 2026-09-01
Статус: Accepted

## Контекст

`parsers/kff/pipeline.py::import_full_match` не проверяет "уже
обработано" — `sync_recent_matches` (`parsers/tasks.py`) периодически
повторно импортирует последние N завершённых матчей (досылка статистики,
исправления на стороне KFF и т.п.). Два независимых случая, где это
периодическое повторное чтение молча портило уже зафиксированные
исторические данные.

### 1. Тренер завершённого матча переписывался при каждом ресинке

`import_coaches` при каждом вызове проверял, распознаётся ли роль как
"главный тренер", и при совпадении переписывал `home_coach`/`away_coach`
на тренера из свежего ответа KFF — даже если матч давно завершён и тренер
там был другой на момент игры. Замечено на живом примере: у тренера,
пришедшего в клуб на 2 матча, счётчик матчей показывал 21 (весь сезон
клуба), потому что он тихо "натягивался" на все прошлые матчи при каждом
ресинке (см. `docs/BACKLOG.md`, находка 4).

**Решение**: как только матч `finished` и поле тренера уже заполнено —
считаем это зафиксированным историческим фактом и больше не трогаем.
Для `scheduled`/`live` обновление по-прежнему разрешено (состав ещё может
уточняться).

### 2. Обрезанный ответ API мог снести реальные события матча

Импорт событий удаляет из БД события, которых нет в текущем ответе API
("устаревшие"). Если бы ответ KFF пришёл HTTP 200, но с обрезанным/
частичным списком событий — такое удаление снесло бы реальные события
матча и каскадно `EventReaction` (реакции пользователей). Явного признака
"ответ неполный" API не даёт.

**Решение**: эвристика по объёму — если новый набор событий от API
существенно (менее чем наполовину) короче того, что уже есть в БД для
этого матча, это подозрительно похоже на обрезанный ответ, а не на
реальное исчезновение событий. В этом случае добавление/обновление новых
событий из ответа выполняется как обычно, но "устаревшие" события не
удаляются — вместо этого пишется warning для ручного разбора.

## Альтернативы и почему не они

- **Полностью отключить удаление устаревших событий** — отклонено:
  реальные удаления/отмены событий на стороне KFF (например, отменённый
  VAR-гол) — легитимный случай, который эта логика должна продолжать
  обрабатывать.
- **Требовать явного признака "полный ответ" от API** — недоступно: KFF
  не предоставляет такого поля.

## Последствия

- Обе защиты — эвристики по данным, а не структурные гарантии; порог 50%
  для находки №2 подобран вручную и может потребовать пересмотра, если
  реальные короткие матчи (мало событий) начнут ложно попадать под него.
- В коде на местах обеих находок остаётся однострочная ссылка на этот файл.
