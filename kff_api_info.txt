Полный разбор API сайта kffleague.kz

(документ для разработки парсера)

1. Общая архитектура

Сайт использует REST API версии v1.

Базовый URL:

https://kffleague.kz/api/v1

Все данные страницы матча загружаются через API.
HTML страницы фактически только оболочка.

Страница матча:

https://kffleague.kz/matches/{match_id}

данные для неё приходят из нескольких endpoints.

2. Основные сущности API

Система состоит из следующих основных сущностей:

Season
Tournament
Team
Game (Match)
Lineup
Player
Coach
Referee
Event
Match Stats
Player Stats
3. Основные endpoints
3.1 Матч

Endpoint:

GET /api/v1/games/{match_id}

Пример:

/api/v1/games/898

Возвращает общую информацию о матче.

Основные поля
поле	описание
id	ID матча
date	дата
time	время
tour	тур
season_id	сезон
stage_name	стадия
status	scheduled / live / finished
home_score	голы хозяев
away_score	голы гостей
minute	текущая минута
half	тайм
Команды
home_team
away_team

Структура:

id
name
logo_url
score
Стадион
stadium
id
name
city
field_type
Судья

В game возвращается только главный судья строкой

referee

Полный список судей приходит из другого endpoint.

9. Замены (substitutions)

Замены хранятся как event:

event_type = substitution

Поля:

minute
player_id   (player_out)
player2_id  (player_in)
10. Minute In / Minute Out

Minute in/out не хранится напрямую.

Оно вычисляется из событий.

Алгоритм:

стартовые игроки
minute_in = 0
если игрок заменён
minute_out = substitution.minute
игрок вышел на замену
minute_in = substitution.minute

12. Новости матча

Endpoint:

GET /api/v1/games/{match_id}/news

используется для новостей на странице матча.

Для парсера обычно не нужен.

пример:

Используется endpoint:

15. Полная схема загрузки страницы матча

Когда пользователь открывает страницу матча:

/matches/{id}

сайт делает запросы:

games/{id}
games/{id}/lineup
live/events/{id}
games/{id}/stats
games/{id}/news
16. Архитектура данных матча

Фактическая модель:

Game
 ├── Teams
 ├── Stadium
 ├── Referees
 ├── Coaches
 ├── Lineups
 │      ├── Starters
 │      └── Substitutes
 ├── Events
 │      ├── Goals
 │      ├── Cards
 │      └── Substitutions
 └── Stats
        ├── Team Stats
        └── Player Stats
17. Минимальный набор API для парсера

Чтобы полностью собрать матч достаточно 4 endpoints:

/games/{id}
/games/{id}/lineup
/live/events/{id}
/games/{id}/stats

Это покрывает 100% информации страницы.

18. Как писать парсер

Алгоритм:

for match_id in season_matches:

    game = /games/{id}

    lineup = /games/{id}/lineup

    events = /live/events/{id}

    stats = /games/{id}/stats

Затем:

build lineups
process substitutions
calculate minute_in minute_out
save events
save stats
19. Главная проблема API

Minute In / Minute Out не хранится в API.

Его нужно вычислять.

Это единственная логика.

Как вычисляется minute_in / minute_out

Это важно.

В API они не приходят.

Они вычисляются из:

game_event
event_type = substitution

пример:

63' substitution
player_out = 7
player_in = 14

значит

player_out minute_out = 63
player_in minute_in = 63
